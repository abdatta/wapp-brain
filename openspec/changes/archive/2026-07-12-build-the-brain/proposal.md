## Why

The archive is now trustworthy (identity-canonical, media-complete, live-synced) but it is still only a *record*. The second-brain layer that was supposed to make it *useful* is a stub: memory pages are extractive-only (the Codex call discards its response), retrieval is a `LIKE` scan with no ranking, there is no global search, no scheduler, and no durable write path.

This change builds the **operational spine** of the brain — the load-bearing foundation the rest of the roadmap stands on: instant full-text search over every message, a durable provider-backed assimilation substrate (task queue, per-chat watermarks, run jobs, token ledger), and the scheduling/catch-up/staleness machinery that keeps coverage truthful for months without babysitting. The higher tiers that turn this substrate into product — the final extraction contract, the person/identity model, the knowledge graph, semantic rollups, the retrieval pipeline, and agent (MCP) access — are sequenced as their own changes on top of this spine (see `openspec/changes/ROADMAP.md`).

It subsumes the `archive-full-text-and-semantic-search` backlog todo outright (search ships here), and stands up the substrate that `self-updating-memory-schedule` and `mcp-chat-reader-server` were reaching for — those are re-planned as the assimilation and MCP changes downstream.

## What Changes

- **Hot tier / instant search**: SQLite FTS5 index over all messages (resolved identity text + body + caption), maintained at ingest, plus a `message_mentions` relation — every message is searchable the moment it lands, with sender/chat/date/type/direction filters and deep links into the thread view. No LLM in this path. *(Delivered, Phase 1.)*
- **Brain substrate**: additive `brain_*` schema (watermarks, durable task queue, run objects, token ledger) landing alongside the existing `memory_*` subsystem — **no teardown here**; the `memory_*` removal is deferred to `memory-teardown-and-docs` so the brain can be validated at parity first. *(Delivered, Phase 2.)*
- **Model provider boundary**: a real `BrainModelProvider` interface with three adapters — `claude-cli` (spawns the user's Claude Code CLI through a WSL bridge; the $0 default), `codex` (existing OAuth client, response actually parsed now), and `extractive` (no-LLM fallback). Remote providers stay explicit opt-in; provider health is monitored with visible "degraded since" status and consecutive-failure alerts; provider and model are selectable from the UI. *(Delivered, Phase 2.)*
- **Episodic substrate**: a durable, queue-driven assimilation pass that segments new conversation into **episodes** — per-chat cited digests generated by an LLM through the task queue. Every claim must cite exact `source_message_key`s or the revision is rejected (retry → extractive fallback, never a block). Per-chat **watermarks** advance only on commit, so coverage is always truthful regardless of crashes, sleeps, or weeks offline. The manual run path is delivered; the remaining spine work is the scheduler/dueness, startup catch-up audit, full run-job objects, and edit/delete/interpretation staleness. *(Phase 3 — in progress.)*
- **Position taken**: the "conversation only" visible-exchange filter governs LLM evidence selection; system/reaction/encrypted-update rows are indexed for search but never consume token budget.

## Capabilities

### New Capabilities

- `archive-full-text-search`: indexed global message search — FTS5 over resolved text, ingest-time maintenance, filters, snippets, deep links, `message_mentions`, rebuildable index under `.wapp-brain/`.
- `brain-model-provider`: pluggable LLM provider boundary — claude-cli/codex/extractive adapters, explicit remote opt-in, user model selection, structured-JSON generation contract, health monitoring and honest degradation states, no prompt/body logging.
- `brain-assimilation`: the tiered write **substrate** — per-chat watermarks, durable task queue, cited episode extraction with mandatory citations, manual-first run control, scheduler with dueness + catch-up, edit/delete/interpretation staleness propagation, token budget ledger, non-blocking operation. *(The semantic tier — knowledge graph, rollups, salience/decay, quality-regression guard, page/overview projection — is re-specified by `knowledge-graph-foundation`, `semantic-rollups`, and `commitment-lifecycle`.)*

### Deferred To Downstream Changes

- `brain-retrieval` (progressive-disclosure read path) → `brain-retrieval-pipeline`, with the review's layered-merge, coverage-verdict, and pinned-deep-path amendments.
- `brain-mcp-access` (grant-scoped agent surface) → `mcp-agent-surface`, adding the answer-shaped `brain_ask`, spend-authority grants, and a weak-model acceptance gate.
- Supersession/teardown of `self-updating-second-brain-memory` and `cited-memory-query` (the `memory_*` subsystem) → `memory-teardown-and-docs`. This change lands additively; nothing is removed until the brain reaches parity.

## Impact

- **New code (this change)**: `src/server/search/` (FTS query layer), `src/server/brain/` spine modules — `provider.ts`, `episodes.ts`, `scheduler.ts`, run-job plumbing; brain/search DTOs in `src/shared/types.ts`. *(Sibling modules `retrieval.ts`, `rollups.ts`, `graph.ts`, `src/server/mcp/` land with their own changes.)*

No `memory_*` tables dropped here.
- **Server/CLI/config**: `/api/search`, `/api/brain/*` (job-based runs with progress, SSE `brain-updated`), CLI `search:reindex` + `brain-*` subcommands, `WAPP_BRAIN_*` env vars; live maintainer gains a post-ingest brain hook (`onArchiveChanged`) and an appended recovery-tick pass (after media, preserving starvation order).

- **Docs/tests**: `.env.example`, plus spine-facing ARCHITECTURE/SECURITY/TESTING/ROADMAP updates (the full docs pass is `memory-teardown-and-docs`); vitest suites with synthetic fixtures, schema additivity, idempotency, privacy canaries.
- **External dependency**: `claude` CLI presence for LLM generation (graceful extractive degradation when absent).

## Scope Revision (trimmed 2026-07-12)

Following the 2026-07-11 architecture review (multi-agent, 26 adversarially-verified findings), this change was **narrowed to the operational spine**: search foundation + brain substrate (delivered), run-job objects, scheduler/dueness, startup catch-up audit, and edit/delete/interpretation staleness. As of 2026-07-12 the artifacts are trimmed to match — the extraction contract, identity/person model, evaluation, semantic tier, retrieval pipeline, MCP surface, historical backfill, and memory teardown now live as fifteen sequenced changes (see the supersession map in `tasks.md` and the dependency chart in `openspec/changes/ROADMAP.md`), each carrying the review's design amendments. The design decisions **D1–D13 in `design.md` remain the architectural baseline for the whole brain** and are referenced by the downstream changes; this change implements the spine subset (D1 hot/episodic tiers, D2 watermarks, D3 queue, D4/D4a scheduling + manual-first, D9 provider, D10 FTS), while the later decisions (D5 final contract, D6 graph, D7 retrieval, D8 anti-rot, D11 MCP, D12 backfill) are realized by their owning changes.
