# Semantic Rollups

> Proposal-level seed (2026-07-11; premises re-verified against the codebase 2026-07-16; reconciled 2026-07-20 against the now-shipped `commitment-lifecycle` (10) and `graph-explorer` (23), and against prompting research on strong-model anchoring). Expand with `/opsx:propose` when scheduled. See `openspec/changes/ROADMAP.md` for ordering and dependencies. **Recommended model: Fable** — drives the design/implementation session; the rollup engine itself calls a *strong runtime tier* (Sol / Fable-Opus, never Luna) at HIGH effort, per call.

## Why

The semantic tier — entity/topic/chat pages and the overview, consolidated weekly from episode claims — is where the strong-model budget goes and where rot risk concentrates (whole-document LLM rewrites). **None of it is built yet**: the rollup task kinds are declared in the queue but retired in the spine executor, and the only page generator in the tree is the legacy `memory_*` consolidator (from raw messages, slated for removal by #15) — so this change builds the brain-tier engine fresh from claims. The review found the original plan's guard (the frozen **D8** baseline in `build-the-brain`'s design — design-only, never coded) both too loose and too strict: the 30%-drop heuristic silently passes stale-claim drops below the threshold while blocking legitimate bulk consolidation, each revision diffs only against its predecessor (so an omission self-ratifies), rollup input selection at the input cap is unspecified (busy entities silently truncate), and there is no claim-level supersession — cross-episode consistency rests entirely on the model noticing conflicts. This change builds rollups with those defects designed out.

**Design stance — determinism for recall & verification, never suggestion (2026-07-20).** The consolidation model is a *strong* tier, and prompting research is consistent that strong models anchor *harder* on injected candidate answers than weak ones and cannot be reliably instructed off them, while coarse-heuristic hints are "signal-shaped noise" that degrades output. So deterministic scaffolding here serves **recall** (making sure the model *sees* the right real claims) and **verification** (checking what it *produced*) — never **suggestion** (pre-biasing its conclusions with our candidate answers). The strong model keeps the judgment; determinism keeps the plumbing. This sharpens the roadmap's "deterministic first, model second" for the highest-stakes model call in the system. Grounding and output-verification constraints are retained in full; only answer-suggesting input scaffolding is removed.

## What Changes

- **Rollup engine**: a new brain-tier engine writing entity/topic/chat pages from episode *claims* only (never raw messages — this is what bounds cost at 326k-message scale; and never from prior page prose — each revision is one generation from ground truth, so drift cannot compound), weekly-cadence dueness plus on-demand, manual-first. The model returns **structured statements with claim refs**; the markdown page is a *deterministic render* of that structure — the model never writes the document, which turns the regression guard from a threshold heuristic into exact accounting (see design.md). The overview is a fully deterministic L0 projection (zero model calls). Consolidation calls are strong-model, HIGH-effort, per-call — the "strong model consolidates" tier, reusing the `generateStructured` provider boundary and the per-call `model`/`effort` overrides the lifecycle sweep already established at HIGH effort. Monthly episode compression is explicitly **deferred out of this change** (measure retrieval noise in #12 first; episodes remain the permanent citation spine either way).
- **Declared supersession** *(output verification)*: nullable `superseded_by_claim_id` on `brain_claims` (no such column today); the rollup JSON must carry `{supersedes: [claim_id]}` whenever prior-revision claims are dropped, so the regression guard distinguishes *declared* supersession (allowed, recorded) from *unexplained* shrinkage (rejected) — fixing both failure modes of the quantity-only heuristic. This is a cheap reporting contract on the output, not a reasoning constraint; the guard triggers only on large unexplained shrinkage so it never bullies the model into retaining stale claims.
- **Conflict handling — recall + verify, never suggest**: the deterministic conflict detector (same entity + same claim kind + overlapping topic across episodes) is used two anchoring-free ways, never as a prompt hint. **(1) Recall**: it drives input **co-location** so both sides of a likely conflict land in the same window, presented as ordinary dated claims with *no "conflict" label* — the model discovers and adjudicates freely (this is also the only anchoring mitigation the literature found to work: both sides, neutral, no direction). **(2) Verify**: a post-write pass re-runs the detector over the committed claim set and raises any residual contradiction as a `brain_validation_issues` flag (optionally a bounded re-roll) — a weak detector yields a cheap, visible flag, never corrupted page content. The self-join is the shape that wedged #10's first lifecycle run (quadratic entity self-join → 606k pairs, event-loop stall), so it MUST be bounded, set-based SQL over composite indexes and `EXPLAIN QUERY PLAN`-verified on a real-DB copy before shipping.
- **Input selection — feed more, select only on overflow** *(recall, not opinion)*: claims are small next to messages and the consolidation tier's context is large, so pre-selection is a fallback, not the default — prefer feeding the full model-generated claim set for an entity, keeping the whole-window path the common case. Only when an entity overflows the input budget do tiered quotas apply (open commitments/questions [from `commitment-tracking`'s `listBrainLifecycleItems`] → conflict co-location pairs → salience/recency to fill), optimized for *coverage/diversity* rather than an importance opinion. Selected claim ids persist on the doc revision so exclusions are auditable and the guard distinguishes "not fed" from "fed and dropped".
- **Embedded closure (implement, don't re-decide)**: `commitment-lifecycle` (10) shipped the single resolutions contract and reserved its embedding here (its design §L8; code seam commented at `runJob.ts`). A rollup call embeds that change's `{resolutions:[{node,status,cites,note?}]}` fragment verbatim and applies it via `applyBrainLifecycleTransitions` inside the same page-rewrite transaction, under the same closed-world postdating rule (cites must be message keys the rollup input actually contained; the writer re-checks independently). The standalone sweep remains as the page-free closure path; this change also resolves #10's deferred open question — sweep cadence vs. rollup scheduling.
- **Regression guard + rollback** *(output verification)*: claim/citation-set diff against prior revision with the declared-supersession channel; refusal raises a visible `brain_validation_issues` row (the table exists — this adds a rollup writer/reader) and keeps the prior revision current; retained revisions; mechanical `brain rollback <doc>`. Deterministic and free (no model call).
- **Extractive quarantine (already pinned — implement, don't re-decide)** *(grounding: remove known-junk)*: `episode-contract-v2` shipped the spec rule "Extractive Claims Never Consolidate" (`brain-assimilation` spec). This change implements the predicate in the rollup input selector — a JOIN excluding claims whose episode has `generator='extractive'` (generator is episode-level; claims inherit it via `episode_id`) — so placeholder filler cannot launder into the semantic tier.
- **Rendered claim dating** *(grounding: temporal context)*: the rollup input renderer prefixes each claim with its episode date range (or min citation timestamp) so legacy or deictic claim text arrives dated at the semantic tier.
- **Markdown projection + graph deep-link**: pages/overview project to the Obsidian vault with frontmatter, wikilinks, claim anchors, stubs for merged/superseded docs; `brain project --rebuild`. Only episodes project today — the entity/topic/chat pages, the wikilink writer, and their routes are all new, keyed on the immutable node `slug` (the designated projection/URL currency, honoring `merged_into` redirects so links never dangle). These pages also complete `graph-explorer` (23)'s deferred integration: a graph node click-throughs to its page, and each page carries a "view in graph" back-link. The projected wikilinks double as the *ambient* Obsidian graph view (untyped, no time axis, baked at write time); the interactive, typed, evidence-linked lens is `graph-explorer` (23), now shipped.
- **Checkpoint**: after a week of episodes, entity pages read as coherent dossiers with citations resolving to exact messages; a stub-model rollup that drops half its claims without declaring supersession is refused and the prior revision stays current; `brain rollback` restores mechanically.

## Capabilities

### New Capabilities

- `semantic-consolidation`: the semantic tier as its own capability (the same move `commitment-tracking` made) — structured consolidation output, deterministic input selection with persisted audit, conflict recall + post-write verification, the exact regression guard with declared supersession, embedded lifecycle resolutions, manual-first rollup runs, deterministic markdown projection + overview, rollback/revision history, and the docs read surface. Implements `brain-assimilation`'s already-pinned "Extractive Claims Never Consolidate" rule as-is (no delta to that spec) and embeds `commitment-tracking`'s resolutions contract verbatim.

### Modified Capabilities

- `client-navigation`: gains routed brain-page surfaces (list + per-doc) with reciprocal deep links with the `/graph` explorer.

## Impact

- **Schema**: new `brain_docs` (doc identity + current revision + dueness cache), `brain_doc_revisions` (retained revisions: statements, declared drops, fed-claim audit), `brain_doc_revision_claims` junction (which docs cite which claims — the staleness/queryability spine); new `superseded_by_claim_id` column on `brain_claims` (projection; revisions are the durable truth); a new rollup writer/reader over the existing `brain_validation_issues` table.
- **Code**: new `src/server/brain/rollups.ts` (engine, guard, conflict detector used for co-location + post-write verify, input selector); wikilink/page projection writer + `brain project --rebuild`; `brain rollback` command; a rollup run-kind handler wired into the spine executor (rollup kinds are currently retired in `scheduler.ts`). Reuses `applyBrainLifecycleTransitions` (no duplicate closure logic) and `generateStructured` (strong model + HIGH effort). Does **not** touch the legacy `memory_*` consolidator (#15 removes it).
- **Docs**: the D8 amendment (declared supersession) and final D1 rollup rules recorded in this change's own design.md — the archived `build-the-brain` design.md is a frozen baseline.
- **Tests**: rollup from claims only, declared vs unexplained shrinkage, conflict recall co-location (both sides in-window, unlabelled) + post-write contradiction flag + the detector's query plan (bulk/bounded, no wedge), input-quota determinism + audit (overflow-only), embedded closure via the shared writer, rollback, extractive quarantine, projection determinism + merged/superseded stubs.
- **Depends on** (both landed): `knowledge-graph-foundation` (9) — pages target nodes, keyed on immutable slugs; `commitment-lifecycle` (10) — §L8 pins the resolutions contract this change embeds. Soft: `graph-explorer` (23, shipped) — entity pages become its node click-through targets and gain "view in graph" back-links.
