## Why

The archive is now trustworthy (identity-canonical, media-complete, live-synced) but it is still only a *record* — the second-brain layer that was supposed to make it *useful* is a stub: memory pages are extractive-only (the Codex call discards its response), retrieval is a `LIKE` scan with no ranking, there is no global search, no graph, no scheduler, and no way for an agent to consume any of it. This change builds the brain itself: a self-updating, evolving knowledge layer over the archive that powers semantic-quality search and agent access at ~$0/month on laptop hardware, without embedding APIs.

It subsumes four backlog todos that were always one system: `archive-full-text-and-semantic-search`, `mcp-chat-reader-server`, `self-updating-memory-schedule`, and the search/evidence half of `thread-view-signal-vs-noise`.

## What Changes

- **BREAKING**: The `memory_*` subsystem (tables, `/api/memory/*` routes, `memory:*` CLI, `.wapp-brain/memory/` layout) is replaced wholesale by the brain. No migration; derived data is rebuilt from the archive (sanctioned: no backward-compat constraints; `identity_version` refuse-and-rebuild precedent).
- **Hot tier / instant search**: SQLite FTS5 index over all messages (resolved identity text + body + caption), maintained at ingest, plus a `message_mentions` relation — every message is searchable the moment it lands, with sender/chat/date/type/direction filters and deep links into the thread view. No LLM in this path.
- **Episodic tier**: a scheduled nightly (and volume-triggered) assimilation pass segments new conversation into **episodes** — per-chat cited digests generated by an LLM through a durable task queue. Every claim must cite exact `source_message_key`s or the revision is rejected. Per-chat **watermarks** advance only on commit, so coverage is always truthful regardless of crashes, sleeps, or weeks offline; startup catch-up drains the backlog rate-limited under a daily token ledger.
- **Semantic tier**: weekly rollups consolidate episodes (never raw messages) into entity/topic/chat pages and an archive overview — an explicit knowledge graph (people, chats, topics, events, commitments, facts) stored in SQLite with a rebuildable Obsidian-compatible Markdown projection under `.wapp-brain/brain/`. Old episodes compress into monthly digests; salience decay hides (never deletes) dormant nodes.
- **Progressive-disclosure retrieval**: one query pipeline serving UI, CLI, and MCP: overview → entity/topic pages → episodes → exact cited messages with context. Fast path is pure BM25 + graph boosts (<2s, no LLM); deep path adds cached LLM query expansion, graph traversal, and citation-validated synthesis as a progress-reporting job. Answers always carry per-chat coverage/freshness metadata so a gap is never presented as an absence.
- **Model provider boundary**: a real `BrainModelProvider` interface with three adapters — `claude-cli` (spawns the user's Claude Code subscription CLI; the $0 default), `codex` (existing OAuth client, response actually parsed now), and `extractive` (no-LLM fallback). Remote providers stay explicit opt-in; provider health is monitored with visible "degraded since" status and consecutive-failure alerts.
- **MCP server**: a separate stdio process, disabled by default, talking only to the loopback HTTP API, exposing brain tools behind user-managed scoped grants (chat/person/time-window/layer) with a full audit log.
- **Position taken**: the "conversation only" visible-exchange filter governs LLM evidence selection; system/reaction/encrypted-update rows are indexed for search but never consume token budget.

## Capabilities

### New Capabilities

- `archive-full-text-search`: indexed global message search — FTS5 over resolved text, ingest-time maintenance, filters, snippets, deep links, `message_mentions`, rebuildable index under `.wapp-brain/`.
- `brain-assimilation`: the tiered write path — per-chat watermarks, durable task queue, episode extraction with mandatory citations, weekly rollups, knowledge graph nodes/edges, compression/decay, staleness propagation from identity merges/edits/deletes, scheduler with catch-up and backfill, token budget ledger.
- `brain-retrieval`: the progressive-disclosure read path — layered query results (overview/page/episode/message) with citations, fast/deep search split, coverage-and-freshness qualification, structured server-side DTOs consumed identically by UI, CLI, and MCP.
- `brain-model-provider`: pluggable LLM provider boundary — claude-cli/codex/extractive adapters, explicit remote opt-in, structured-JSON generation contract, health monitoring and honest degradation states, no prompt/body logging.
- `brain-mcp-access`: grant-scoped agent access — stdio MCP server, disabled by default, per-scope grants with expiry, layer-capped defaults, audit log of every tool call (keys and counts, never bodies).

### Modified Capabilities

- `self-updating-second-brain-memory`: superseded — all requirements removed; consolidation, provider opt-in, run ledgers, and citation rules are re-specified (stronger) under `brain-assimilation` and `brain-model-provider`.
- `cited-memory-query`: superseded — all requirements removed; layered cited retrieval is re-specified (stronger) under `brain-retrieval`.

## Impact

- **New code**: `src/server/brain/` (scheduler, tasks, episodes, rollups, graph, retrieval, provider), `src/server/search/` (FTS query layer), `src/server/mcp/` (stdio server); brain DTOs in `src/shared/types.ts`.
- **Removed code**: `src/server/memory/` write paths, `/api/memory/*` routes, `memory:*` npm scripts (rebuild replaces migration).
- **Repository**: additive schema in `sqliteRepository.ts` — `messages_fts`, `message_mentions`, `brain_nodes/edges/aliases`, `brain_episodes`, `brain_claims/citations`, `brain_doc_revisions`, `brain_tasks`, `brain_chat_watermarks`, `brain_runs`, `brain_llm_ledger`, `brain_grants`, `brain_access_log`, job locks; `memory_*` tables dropped; mirrored in `MemoryArchiveRepository`.
- **Server/CLI/config**: `/api/search`, `/api/brain/*` (job-based runs with progress, SSE `brain-updated`), CLI `brain-*` subcommands, `WAPP_BRAIN_*` env vars; live maintainer gains a post-ingest brain hook (`onArchiveChanged`) and an appended recovery-tick pass (after media, preserving starvation order).
- **UI**: global search panel; brain status/overview panel replacing the memory panel.
- **Docs/tests**: ARCHITECTURE, SECURITY_AND_PRIVACY, TESTING, LIMITATIONS, ROADMAP, `.env.example`; vitest suites with synthetic fixtures, schema additivity, idempotency, privacy canaries; four backlog todos absorbed/retired.
- **External dependency**: `claude` CLI presence for LLM generation (graceful extractive degradation when absent); optional `@modelcontextprotocol/sdk` for the MCP server.

## Scope Revision (2026-07-11)

Following the 2026-07-11 architecture review (multi-agent, 26 adversarially-verified findings), this change is **narrowed to the operational spine**: search foundation + brain substrate (delivered), run-job objects, scheduler/dueness, startup catch-up audit, and edit/delete/interpretation staleness. The extraction contract, identity/person model, evaluation, semantic tier, retrieval pipeline, MCP surface, backfill, and teardown are re-planned as fifteen sequenced changes with the review's design amendments baked in — see `openspec/changes/ROADMAP.md` for the full dependency chart and supersession map. The design decisions D1–D13 in `design.md` remain the architectural baseline; the new changes amend specific decisions (D5, D6, D7, D8, D12) as recorded in their proposals.
