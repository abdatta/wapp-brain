# Reply Quote Recovery

> Proposal-level seed (2026-07-13). Expand with `/opsx:propose` when scheduled. See `openspec/changes/ROADMAP.md` for ordering and dependencies. **Recommended model: Opus.**

## Why

`evidence-pack-fidelity` (2) shipped quoted-reply stitching, but its referent resolution has a hole: when the quoted message is not in the pack it falls back to a same-chat database lookup (`resolveQuotedReferents`, scoped `WHERE chats.source_chat_id = ?`), and when *that* misses it degrades to a bare `↳ replying to an earlier message`. That lookup misses three real cases — a reply to a message older than the pack window, a reply to a since-deleted message, and a **cross-chat quote** (WhatsApp's *Reply Privately*, where the quoted message lives in a group but the reply lands in a 1:1). In all three the antecedent vanishes from the model's view, which is exactly the referent-misattribution failure class the Gate 2.7 digest flagged as the headline defect.

WhatsApp never resolves any of this at read time — it stores a **self-contained, chat-local snapshot** of the quoted message alongside every reply (`message_quoted.text_data`, plus the original's sender, `key_id`, timestamp, and type). The reply carries its own antecedent; restoring a backup just replays the copy. Verified against the real archive (modern Android `msgstore.db`, crypt15): **38,846 replies, 37,268 (95.9%) carry recoverable quoted text** the current importer discards — it keeps only the foreign-key pointer. Text-message quotes recover essentially 100%; the ~4% shortfall is media quotes with no text to recover. A spot check confirmed a group→1:1 *Reply Privately* ("ye numbers kaha se laara bhai" → a full "SUMMER SUBLEASE" listing) recovers intact, chat-locally, with no cross-chat query. This must land **before `historical-backfill` (14)**: capturing quotes after the one-shot extraction would force the re-extraction that `episode-contract-v2` exists to avoid.

## What Changes

- **Import capture (full snapshot family)**: parse the `message_quoted` snapshot at import (modern Android confirmed; legacy Android / iOS `ChatStorage` store it differently, so capture is best-effort with graceful fallback to today's pointer when the snapshot is absent) and persist the quoted message's **full text**, sender JID, `key_id`, timestamp, and type on the reply. **The stored quoted text is never truncated** — the snapshot is the source of record. When the quoted message was itself media, a location, or a contact card, its snapshot companions are captured too — `message_quoted_media` (thumbnail/caption/mime; **4,084 rows** in the archive), `message_quoted_location`, `message_quoted_vcard`, and `message_quoted_mentions` — so a reply to an image, a shared location, or a forwarded contact recovers that context, not just an empty "media" marker.
- **Snapshot-first referent rendering**: replace the fragile `resolveQuotedReferents` same-chat lookup with the stored snapshot. Rendering order stays tiered — the quoted message's in-pack alias when present (citable), otherwise the snapshot's **full** quoted text as non-citable context (covering out-of-window, deleted, and cross-chat referents), otherwise the generic fallback only when no snapshot exists. **The full quoted text is rendered in evidence with no length cap** — reply-quote context is not subject to a token budget (explicit decision); density budgets govern claims and summaries, not recovered antecedents.
- **Quoted sender as a resolution input**: the captured quoted-sender JID resolves through the existing `contactLabelSql` chain for its label and joins the pack-local entity-resolution set, so a claim about the quoted person anchors to identity like any participant. Push-name provenance and number-token rules apply to quoted senders too.
- **Late-binding row filled**: this closes the long-open "quoted replies" row of the late-binding inventory (Standing Principle 3) — anchor = reply message key + quoted `key_id`; stamp = `extraction_version` + snapshot-present flag; repair = quoted-sender name resolution rides `identity-late-resolution` (4), and a later-imported original can hard-link via `key_id` (beating surrogate matching). Bumps `EXTRACTION_VERSION`; existing episodes are picked up by `brain regenerate`.
- **WhatsApp-style UI quoted bubble**: the thread view renders a reply's quoted message as WhatsApp does — a tinted quote preview above the message with the quoted sender and text, **truncated in the UI when long** (clamped lines with an ellipsis; tap to expand, or scroll to the original when it is present in the thread). UI truncation is display-only and never touches the stored or assimilated text.
- **Checkpoint**: on the real archive, a *Reply Privately* group quote renders its full quoted text in the episode evidence and a truncated bubble in the thread UI; a reply to a quoted *image* renders its caption/thumbnail context rather than a bare marker; `brain regenerate` upgrades pre-change episodes so their reply lines carry the antecedent; a reply whose original is a since-deleted message still shows the recovered text; a source without a snapshot falls back to the pointer/generic path with no regression.

## Capabilities

### Modified Capabilities

- `brain-assimilation`: Evidence Selection Policy amended — quoted-referent resolution reads the captured snapshot (full text, no cap) before the same-chat lookup, quoted senders join pack-local entity resolution, and the quoted-reply late-binding stamp is recorded; `EXTRACTION_VERSION` bump with regeneration.
- `whatsapp-style-thread-view`: reply messages render a WhatsApp-style quoted-message bubble (sender + text, UI-side truncation with expand, jump-to-original when in-thread).

## Impact

- **Code**: `src/server/import/parser.ts` (parse `message_quoted` snapshot for modern + graceful fallback for legacy/iOS), `src/server/db/sqliteRepository.ts` + mirror (schema for the quoted snapshot, evidence query returns it, commit path), `src/server/brain/episodes.ts` (snapshot-first tiered rendering, quoted-sender resolution, `EXTRACTION_VERSION` bump), client thread view (quoted bubble with UI truncation).
- **Schema**: quoted-snapshot fields on the reply (columns on `messages` or a dedicated snapshot table carrying full `text_data`, quoted sender JID, `key_id`, timestamp, type); no wipe of the archive layer; derived brain tables regenerate via the contract-v2 machinery.
- **Tests**: modern-schema snapshot capture, full-text (untruncated) storage, snapshot-first rendering for out-of-window/deleted/cross-chat referents, quoted-sender label + entity anchoring, legacy/absent-snapshot fallback (no regression), regeneration upgrades old episodes, UI truncation is display-only.
- **Depends on**: `episode-contract-v2` (3) — evidence rendering, `EXTRACTION_VERSION`, and the regeneration path this rides; builds on `evidence-pack-fidelity` (2, archived) whose stitching this supersedes. Ordering: **must precede `historical-backfill` (14)** so the archive is assimilated with quotes already captured.

## Relationships to planned changes (impact scan)

- **`historical-backfill` (14)** — capture-before-spend prerequisite (same class as `demask-contact-labels`): quotes must be captured before the one-shot extraction or backfill would need re-running. Dashed dependency edge added.
- **`commitment-lifecycle` (10)** — enhanced: a reply structurally links an answer to the message it answers, and the recovered quoted text of a commitment ("did you send it?" → quote of the promise + "done ✅") sharpens `resolves` and question→answer detection.
- **`knowledge-graph-foundation` (9)** — enhanced: the captured reply→quoted relationship can seed a `replies_to`/`responds_to` edge kind, feeding the commitment `resolves` edge; graph edges stay out of scope here (capture + rendering only).
- **`two-level-person-model` (5)** — the quoted sender is another pack-local identity anchor; the pack-local resolution rule extends to quoted senders (no global name lookup).
- **`retrieval-hardening` (8)** — consideration only: recovered quoted text for cross-chat/deleted originals is content not otherwise present in that chat; whether to index it (vs. duplicating hits on the original) is a decision for that change, not this one.
- **`brain-eval-harness` (7)** — this change should improve referent-resolution recall; if the harness lands first, it can baseline the delta. No design change to the harness.
- **Not already covered**: `evidence-pack-fidelity` (archived) added pointer-based reply *rendering* only; no change captures the WhatsApp snapshot. This fills the unowned "quoted replies" late-binding row.
