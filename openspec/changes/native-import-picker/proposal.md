## Why

Today the import wizard makes the user select four inputs separately (encrypted `msgstore`, `wa.db`, a key file, and the media folder) and hand-type the media path — because a browser file picker can never reveal an absolute filesystem path. But a real WhatsApp backup is a **single folder** holding the whole standard layout: `msgstore.db.crypt15`, `wa.db.crypt15`, a `Media/` folder, and several auxiliary `.crypt15` databases, all encrypted with **one key**. The user should just point the app at that folder and let it figure out the rest. Because this is a local-first app (browser and server co-located on `127.0.0.1`), the server can open a native folder dialog on the user's own machine, learn the backup folder's absolute path, and auto-detect and read everything **in place** — one click, one key typed in, nothing uploaded. There is no backward-compatibility constraint, so the flow is revamped end to end rather than layered onto the old one.

## What Changes

- **Single backup-folder pick with auto-detection**: the wizard's primary action becomes **"Browse for your WhatsApp backup folder."** A native OS folder dialog returns the folder's absolute path; the server scans it and auto-detects the standard layout — `msgstore` (required), `wa.db` (optional contacts), and the `Media/` folder (optional) — searching the folder and its usual `Databases/` / `Media/` subfolders, and reports what it found *before* import. The four separate picks collapse into one.
- **Everything is a path, read in place — no upload, no staging** (**BREAKING**): the browser byte-upload path and the file-staging machinery (`/api/import/staging/*`, `stageImportFile`, `uploadImportFile`, `ImportStagingFileKind`) are removed. Inputs are always paths — native-picked or typed — read directly from disk, so even the multi-GB `Media/` folder never crosses the browser boundary. The async import **job** model (phase progress + polling + cancel) is kept and simply takes the detected paths.
- **Text-only key** (**BREAKING**): file-based key support is removed entirely — the key file picker, the `keyPath` input, the staged-key flow all go. The key is always provided in the text field and verified locally, and the same key decrypts the whole backup.
- **Responsive, non-blocking setup**: the native pick, the folder scan, and key verification each show a progress/busy indicator and run **without blocking the server event loop** (the dialog runs as a spawned child; the scan uses async I/O and is **shallow**, so it stays fast even beside a multi-GB `Media/` folder; verification runs async). The existing async import-job progress carries the import itself.
- **Auxiliary backup files detected and reserved**: the scan also recognizes the auxiliary databases in the folder — `chatsettingsbackup`, `status_backup`, `offloaded-media`, `backup_settings.json`, `commerce_backup`, `stickers_db` — and surfaces them in the detection report as **found and reserved**. This change does **not** ingest them into features; each is earmarked as a follow-up so downstream consumers get a properly-designed model, and nothing in the backup is silently ignored.
- **Fallbacks without backward-compat baggage**: where the native picker can't run (non-Windows / headless), the wizard lets the user **type the backup folder path** (auto-detected the same way), plus an advanced **typed per-input override** for non-standard layouts. Everything is read in place; there are no uploads anywhere. The web viewer keeps working on every platform.
- **Windows-first native dialog** with a clean per-OS seam (macOS `osascript`, Linux `zenity`) for a later change.

### Modified Capabilities
- `premium-onboarding-workflow`: the import wizard is revamped into a single-folder-pick + auto-detect flow with a text-only key, read entirely in place. The **File Picker Import Wizard** requirement is rewritten around picking one backup folder; **Local Key Verification** drops key-file support; **Privacy-Preserving Staging** is rewritten around reading user files in place (only decrypted intermediates are staged). New requirements cover **Native Local Path Detection** (the folder/file dialog endpoint), **Backup Layout Auto-Detection** (scan → manifest of core inputs plus reserved auxiliary files), and **Non-Blocking Setup Progress** (responsive, event-loop-friendly pick/scan/verify).

## Impact

- **Client**: `src/client/App.tsx` `ImportWizard` reworked to a folder-first flow (Browse folder → detection summary → key text → mode → import) with busy indicators on pick/scan/verify; the key file picker, `useStagedKey`, per-input pickers, and byte-upload are removed. `src/client/api.ts` gains `pickImportPath` and `detectBackupFolder`; `uploadImportFile` and key-file/staging fields are removed.
- **Server**: new `POST /api/import/pick` (native dialog → path) and `POST /api/import/detect` (scan folder → manifest) in `src/server/server.ts`; new `src/server/import/nativePicker.ts` and `src/server/import/detectBackup.ts`. Remove `/api/import/staging/*`; simplify `/api/import/jobs` to take the detected paths + text key + mode.
- **Shared/importer**: `src/shared/types.ts` `ImportRequest` drops `keyPath`; `ImportStagingFileKind` and its staging module are removed. `src/server/import/importer.ts` requires the text key and reads inputs in place; `runImport` still takes resolved local paths and reads with `fs`, so the core import pipeline is unchanged.
- **Privacy/security**: pick/detect endpoints are localhost-only; only a validated `kind` enum and a server-validated folder path cross the boundary; no client string is interpolated into the dialog command; user files are read in place (never copied), only decrypted intermediates are written to the private workspace and cleaned; no key material persisted.
- **Platform**: Windows-first native dialog; other platforms report unavailable and fall back to a typed backup-folder path.
- **Tests**: native picker, folder auto-detection (layout variants, missing/duplicate/dated files, auxiliary recognition), both endpoints, upload/staging + key-file removal, server-responsiveness during a pending pick, and the wizard wiring.
